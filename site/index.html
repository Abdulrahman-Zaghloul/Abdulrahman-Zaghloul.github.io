Civilneer

Automated quality control for roadway engineering drawings. I founded it, built it end to end, and run it for a private beta of 5–10 civil engineers.

On a roadway plan set, every cross section carries printed slopes, elevations and offsets that are supposed to describe the geometry drawn beside them. Often they don't, because the drawing changed and the callout didn't. Checking them by hand falls to the most expensive engineer in the office.

Civilneer takes the vector PDF, rebuilds the cross-section geometry, reads every callout, and returns the same sheet marked up: yellow where the value matches, red where it doesn't, with the measured value, the printed value and the difference on hover. A review that takes an engineer 5–10 minutes per sheet runs in under 5 seconds, and the beta has put more than 180 drawing sheets through it.

The hard part

  • No OCR and no rasterizing: PyMuPDF reads vector paths and text spans straight from the PDF content stream.
  • Each callout is matched to the linework it describes by its position on the sheet, then measured with Shapely and NumPy.
  • Nothing is hidden behind a score. The engineer sees exactly what was measured and makes the call; the published demo run shows 86 geometric checks across 9 cross sections.

Built with Python, FastAPI, PostgreSQL, OAuth 2.0, React, Next.js, PyMuPDF, Shapely and NumPy, deployed with Docker Compose and automated CI/CD.

Ledgerline

A double-entry wallet and payments ledger API. The interesting part isn't the CRUD; it's the guarantees.

The kind of service that sits behind a peer-to-peer payments app: multi-currency wallets, deposits, withdrawals and transfers between users. It is built so money is never created, lost or spent twice, even under concurrent requests, client retries and crashes.

How it holds

  • Every transaction's postings sum to zero, verified by a deferred constraint trigger when it commits.
  • A retried request can't charge twice: the idempotency key, the money movement and the response commit in one transaction.
  • Row locks are taken in one global order, so concurrent transfers can't deadlock. Parallel tests fail if the lock is removed.
  • Events go through a transactional outbox to HMAC-signed webhooks, with backoff and dead-lettering.

Built with FastAPI, PostgreSQL 16, SQLAlchemy, Alembic and Docker. Strict mypy and CI on every push.

Retail Data Lakehouse Pipeline

Six retail source domains to tested, analytics-ready marts, reproducible from one command.

Raw data is extracted from an operational PostgreSQL database and landed as Parquet, cleaned and conformed with PySpark, loaded into a warehouse, and modeled with dbt into customer, product and date dimensions, an order fact table and daily sales marts. Airflow runs the whole thing.

Why it can be trusted

  • 37 dbt tests check keys, relationships, accepted values and source freshness on every build.
  • Python unit tests cover extraction and transformation on their own.
  • Both run in GitHub Actions, so a broken data contract fails the build instead of reaching an analyst.

Built with PySpark, dbt, Apache Airflow, PostgreSQL, Parquet, Docker and GitHub Actions.

Vigil

A lightweight threat-detection engine, built in public one part at a time.

Vigil reads security logs, spots attacks such as SSH brute force and password spraying, and raises alerts mapped to MITRE ATT&CK. Every alert carries the exact log lines that triggered it. It runs as a command-line scanner, stores events in PostgreSQL, and exposes an ingestion and alerts API with scoped keys and rate limits.

Scanning the bundled attack scenario

          5 failed logins within 60s
CRITICAL  ssh-success-after-failures
          'root' logged in after 6 failed attempts

Built with Python, FastAPI, PostgreSQL and SQLAlchemy, with CI on every push.
